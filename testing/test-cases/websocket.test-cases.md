## 测试用例列表

### TC-WS-001: WebSocket连接建立

| 项目 | 内容 |
|------|------|
| 用例ID | TC-WS-001 |
| 用例名称 | WebSocket连接建立 |
| 优先级 | P0 |
| 前置条件 | 用户已登录，持有有效Token |

**测试步骤：**
1. 客户端发起WebSocket连接
2. 携带JWT Token进行认证

**预期结果：**
- 连接成功建立
- 返回连接确认消息
- 用户状态更新为在线

**消息格式：**
```json
// 客户端发送
{
  "type": "connect",
  "token": "jwt_token_here"
}

// 服务端响应
{
  "type": "connected",
  "userId": "user_123",
  "timestamp": 1704067200000
}
```

## 性能测试用例

### TC-WS-PERF-001: 消息延迟测试

| 项目 | 内容 |
|------|------|
| 用例ID | TC-WS-PERF-001 |
| 目标 | 消息延迟 < 100ms |
| 测试方法 | 测量发送和接收时间差 |

**测试步骤：**
1. 客户端发送带时间戳的消息
2. 服务端立即回显
3. 计算往返时间

**通过标准：**
- 平均延迟 < 100ms
- 95%消息延迟 < 200ms
- 无超时消息

## WebSocket消息类型参考

### 客户端消息

| 类型 | 描述 |
|------|------|
| connect | 建立连接 |
| ping | 心跳请求 |
| join_room | 加入房间 |
| leave_room | 离开房间 |
| ready | 准备状态 |
| start_game | 开始游戏 |
| game_action | 游戏操作 |
| end_turn | 结束回合 |
| chat | 聊天消息 |

### 服务端消息

| 类型 | 描述 |
|------|------|
| connected | 连接成功 |
| pong | 心跳响应 |
| room_update | 房间更新 |
| player_joined | 玩家加入 |
| player_left | 玩家离开 |
| player_ready | 玩家准备 |
| game_started | 游戏开始 |
| game_state | 游戏状态 |
| turn_started | 回合开始 |
| turn_ended | 回合结束 |
| chat_message | 聊天消息 |
| error | 错误消息 |
